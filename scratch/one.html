The Strand Survival Knapsack

How seq-ptp-choice-k turns a branching-process model of per-strand token acceptance into a knapsack over strand lengths — the math behind proposals() in src/ptp/lit.py and _greedy_optimal_lengths in scripts/inference.py.

In one line: each candidate strand's accepted-token count is modeled as an extinction time of a shared-frailty branching process; because that frailty acts identically on any subset of surviving strands, the expected total accepted tokens splits into one term per depth, and choosing how long to make each of the k strands becomes a knapsack — items are whole strands, cost is length, value is the depth-separable survival gain, solved exactly by dynamic programming over depth.

1 The generative model

Start with K candidate strands (the choice-k ensemble size, or K=1 for plain seq-ptp). At each depth — generation — i = 1, 2, …, a shared frailty is drawn and thins whatever strands are still alive:

Θi∼Beta(α,β) , Si∣Si−1=m,Θi ∼Binomial(m,Θi) 1.1

Θi is redrawn every generation but shared across all strands alive that round — that shared draw is what correlates strands within a generation. Marginalizing it out gives a Beta-Binomial transition, and

T=min{i≥1:Si=0} , G=1+T 1.2

T (extinction time) is the number of generations until every strand has failed verification; G, accepted tokens per call, is T plus a guaranteed first-token floor.

Reparametrization

Work in (π0,p,ρ) — p is the marginal per-strand success probability, ρ the pairwise correlation between two strands in the same generation:

ν=1−ρρ , α=pν , β=(1−p)ν 1.3

Zero-inflation

A pure Beta-Binomial makes total first-round wipeout vanish as K grows, which the data contradicts — P(T=1) plateaus at a nonzero floor. Give the frailty a point mass at zero:

Θ∼π0δ0+(1−π0)Beta(α,β) 1.4

With probability π0 the round is a guaranteed total wipeout no matter how many strands are alive — a high-entropy position no ensemble size rescues.

v3 fit — hard-coded in SeqPTPChoiceKInference Generation 1 is exempt from zero-inflation (pure Beta-Binomial); generations 2 through cap_t−1 use a constant π0; generation cap_t (= tokens_per_student_call) is a forced death, reflecting the hard proposal-length cap. Joint-MLE fit: π0=0.0616, p=0.713, ρ=0.858 — see _BRANCH_PI0 / _BRANCH_P / _BRANCH_RHO.

2 Expected accepted tokens

No closed form for E[T] in general, but the tail-sum identity makes it a cheap numerical propagation through the transition matrix:

E[T]= ∑i=0∞ P(Si>0) 2.1

This is exactly _branch_survival_table: it builds a table S[w,d] giving the survival probability of a homogeneous run started with w strands, for every depth d up to cap_t. That table is the object everything below is built from.

3 Why strand length choice separates by depth

Choice-k strands don't all have to share one length. Define the width profile:

W(d):=#{s:Ls≥d} 3.1

— the number of strands whose own chosen length budget still reaches depth d. The move that makes this tractable: because Θd applies i.i.d.-conditionally to every strand present that round, any fixed subset of a surviving population is itself Beta-Binomial with the same (α,β) — a standard thinning property. So the subpopulation still alive and still within its own budget at depth d is distributed exactly as a fresh homogeneous run started with W(d) strands, carried out for d−1 steps — independent of every other depth:

E[T]= ∑d S[W(d),d] 3.2

Expected accepted tokens is now a sum of terms that each depend on the width profile at one depth — which is exactly what makes the strand-length choice a separable, knapsack-shaped problem.

4 The knapsack

Choosing k strand lengths L1,…,Lk to maximize expected accepted tokens under a fixed node budget is now:

maxL1,…,Lk ∑d=1cap_t S[W(d),d] s.t. ∑s=1k Ls≤budget 4.1

with W(d)=∑s=1k1[Ls≥d] as in §3. Items are whole strands of length L; cost is L (it bumps width at every depth 1…L together, per the figure above); budget is k⋅tokens_per_student_call by default, or less when a mode reserves part of it for guaranteed full-length strands.

5 Exact solver

The feasible width profiles are exactly the nonincreasing integer sequences W(1)≥…≥W(cap_t)≥0 — any such sequence decomposes into W(d)−W(d+1) strands of length d, via the standard nonincreasing-sequence↔partition correspondence, so this is a DP over depth rather than a heuristic:

Vd[wcap,b]= max0≤w≤min(wcap,b) S[w,d]+Vd+1[w,b−w] 5.1

Vd[wcap,b] is the best achievable ∑d′=dcap_tS[W(d′),d′] given W(d)≤wcap and remaining budget b, with Vcap_t+1=0; the width bound doubles until the optimum stops touching it, so the answer is exact at any budget.

# _exact_optimal_lengths / _solve_width_profile — scripts/inference.py:1932
w_max ← a generous initial guess
repeat:
    surv ← branch_survival_table(w_max, cap_t)   # S[w,d], d=1..cap_t
    for d = cap_t downto 1:  # fill V_d from V_{d+1} via eq. 5.1
        V[d] ← max over w of S[w,d] + V[d+1][w, · − w]
    W(1..cap_t) ← trace back the argmax w at each depth
    if W(1) < w_max: break
    w_max ← 2 · w_max                       # bound was too tight — retry
return W(d) − W(d+1) strands of length d, for each d
Superseded: the greedy heuristic This section originally described a bundled-knapsack greedy: repeatedly buy whichever whole strand maximizes gain(L)/L, where gain(L)=∑d=1L[S[W(d)+1,d]−S[W(d),d]]. It was not provably optimal, just close in practice (within 0.015% of exact by k=50) — the DP above has since replaced it in SeqPTPChoiceKInference, at some extra one-time construction cost since _exact_optimal_lengths runs once per __init__, not per proposal round.

6 Tree-based proposals: why non-monotone W(d) doesn't win here

Everything above assumes strands never share tokens. Relaxing that: let two strands agree on their first k positions (a shared trunk) before diverging — verification only pays for the shared prefix once:

cost(s1,s2)= |s1|+|s2|−k 6.1

This is strictly more general than §1–5: a flat forest can only ever produce a nonincreasing W(d) (a strand alive at depth d was necessarily alive at every shallower depth too), while a branch point can inject width at one depth without having paid for it at any shallower one — W(d) can rise and fall. Two corrections to the model are needed to price this correctly. First, during the shared prefix the pair behaves as one lineage, not two correlated ones — contributing S[1,d] for d=1..k, not S[2,d]. Second, the branch's children are gated by that lineage surviving through position k — S[1,k+1] — and then evolve under a separate, no-exemption survival table: the generation-1 π0-exemption (§1) is a one-time, real-depth-1 event, never re-earned by a branch spawned later, regardless of k:

E[T]= ∑d=1kS[1,d] +S[1,k+1] ∑mS2[W(k+m),m] 6.2

Dropping achievability entirely — pretend W(d) can be sized independently at each depth for free — turns the problem into a textbook separable-concave allocation, exactly solved by greedy water-filling (no DP needed, since S[w,d] is concave increasing in w at every d we checked). That ceiling is genuinely non-monotone — at budget 30 it wants W=[1,3,4,4,4,4,3,…], rising before it falls, because depth 1 has zero marginal value (S[w,1]=1 for any w≥1) while depths 2–6 still have plenty.

The catch That ceiling is unbuildable as a real tree without paying for the correlation it ignored. Realizing W(1)=1 then jumping to W(2)=3 forces a 3-way branch off a single root — every downstream node now shares one point of failure. Simulated exactly, that tree scores 3.335, worse than the plain flat optimum. The best real tree found by search (varying trunk depth, root width, and branch factor) reaches 3.4436 — within 0.36% of flat, but never past it.

Mechanistically: sharing trades an ongoing per-node saving for a one-time multiplicative gate, S[1,k+1], that every branch downstream is conditioned on. Under this checkpoint's fit (ρ=0.858) that gate consistently costs more than the freed nodes buy back — not because sharing is never worth it in principle, but because S[w,d] stays meaningfully concave in w at every depth here, not just depth 1. It flips only for a shape this model doesn't have: a depth range where correlation is near-total (extra width is free to give up) followed by a depth range where it genuinely isn't (freed nodes land somewhere they still pay off) — e.g. ρ→1 for the first 10 generations, back to 0.858 after. Nothing in this checkpoint's single, depth-uniform (π0,p,ρ) produces that shape, which is why flat wins in practice.
